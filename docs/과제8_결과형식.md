# 과제 8 — 상시 추론 서비스 결과 형식 (v1, 2026-10-21)

## 구성
| 프로세스 | 파일 | 하는 일 |
|---|---|---|
| ts-collector | collector.py | MQTT 센서 업링크 구독 → `~/ts-data/live.db`(SQLite)에 저장. 7일 지난 기록은 지움 |
| ts-infer | service.py | 매분 정각+1초에 최근 2일치를 읽어 전처리(features.py, 학습과 같은 코드) → GRU·오토인코더·MLP(ONNX Runtime CPU) → 결과 발행 |

- 입력은 **마지막으로 다 찬 5분 칸**까지 (예: 10:03 실행 → 09:55~10:00 칸이 "지금"). 학습 때와 같은 5분 평균을 쓰기 위해서.
- 접속 정보는 `~/ts-data/.env` (견본: `service/env.example`). 코드·git에 넣지 않음.

## 결과를 받는 방법
| 방법 | 주소 | 내용 |
|---|---|---|
| MQTT (retained) | `ts-team4/inference/room/office` · `/lab` · `/meeting` | 공간별 최신 결과 (아래 형식). 새로 구독해도 마지막 값을 바로 받음 |
| MQTT (retained) | `ts-team4/inference/status` | 서비스 상태. 서비스가 죽으면 브로커가 `{"alive": false}`로 바꿈(LWT) |
| MQTT | `ts-team4/inference/alarm` | 경보 이벤트(발생·계속·해제). retained 아님 |
| HTTP | `http://<젯슨>:8425/latest`, `/latest/office`, `/alarms`, `/health`, `/rooms` | 같은 내용을 JSON으로 조회 |

공간 이름: office=사무실, lab=실습실, meeting=회의실.

## 공간별 결과 필드
| 필드 | 단위 | 뜻 |
|---|---|---|
| `room` | | 공간 이름 |
| `computed_at` | KST ISO | 계산한 시각 |
| `model_version` | | 서비스·모델 버전 |
| `data_time` | KST ISO | 결과의 기준이 된 5분 칸 시작 시각 (값이 있는 마지막 칸) |
| `data_status.last_reading` / `age_min` / `gap` | KST ISO / 분 / bool | CO₂ 마지막 수신 시각, 지난 시간, 20분 넘게 안 들어왔는지 |
| `co2_now_ppm`, `temperature_now_c` | ppm, ℃ | 지금 칸 값 (없으면 null) |
| `forecast.step_min`, `forecast.co2_ppm` | 분, ppm | 5~60분 뒤 CO₂ 예측 12개 (GRU) |
| `minutes_to_1000ppm` | 분 | 1,000ppm 넘을 때까지 예상 시간. 이미 넘었으면 0, 60분 안에 안 넘으면 null |
| `ventilation.level` | | 정상 / 주의(30분 내 예측 최대 860 이상) / 환기 필요(1,000 이상) / 환기 필요(이미 초과) / 판단 불가 |
| `ventilation.max_30min_ppm` | ppm | 30분 내 예측 최대 |
| `anomaly.rules` | | 걸린 규칙 (급변, 값 고정, 범위 밖, 온도 상승, 계단) |
| `anomaly.score`, `threshold` | | 오토인코더 복원 오차와 경보 기준(검증 기간 0.999 분위수) |
| `anomaly.is_anomaly`, `cause_sensor` | bool, co2/temp | 이상 여부와 원인으로 보이는 센서 |
| `occupancy.prob`, `occupied` | 0~1, bool | 사용 중일 확률 (MLP, 기준 0.35) |
| `alarms` | | 이 공간에서 지금 켜져 있는 경보 목록 |

결측 정책: 최근 2시간에 빈 칸이 있으면 예측은 null(판단 불가), 최근 1시간에 빈 칸이 있으면 오토인코더 점수는 null(규칙만 판단).

### 예시 (`ts-team4/inference/room/office`, 일부)
```json
{"room": "사무실", "computed_at": "2026-10-15T10:03:00+09:00", "data_time": "2026-10-15T09:55:00+09:00",
 "data_status": {"last_reading": "2026-10-15T10:02:00+09:00", "age_min": 1.0, "gap": false},
 "co2_now_ppm": 932.4, "temperature_now_c": 24.6,
 "forecast": {"step_min": [5, 10, 15, 20, 25, 30, 35, 40, 45, 50, 55, 60],
              "co2_ppm": [951.2, 968.0, 983.5, 997.1, 1009.8, 1020.3, 1030.2, 1038.0, 1044.1, 1049.0, 1052.6, 1055.1]},
 "minutes_to_1000ppm": 25, "ventilation": {"level": "환기 필요", "max_30min_ppm": 1020.3},
 "anomaly": {"rules": [], "score": 0.0087, "threshold": 0.0268, "is_anomaly": false, "cause_sensor": null},
 "occupancy": {"prob": 0.93, "occupied": true},
 "alarms": [{"종류": "환기", "설명": "환기 필요: 30분 내 최대 1020ppm", "시작": "2026-10-15T09:48:00+09:00"}]}
```

## 경보
- 종류: `환기`(환기 필요 이상일 때), `이상`, `데이터 끊김`(공간 CO₂ 20분 넘게 없음), `수집 끊김`(공간 "전체", 수집기가 3분 넘게 아무것도 못 받음)
- 중복 억제: 같은 공간·종류는 처음 생길 때 `발생` 1번, 계속되면 60분마다 `계속` 1번, **15분 동안 다시 안 걸려야** `해제` 1번(지속분 포함). 켜졌다 꺼졌다 반복하는 깜빡임을 막기 위함 (가짜 데이터 시험에서 3시간에 발생·해제 38건 → 20건, 깜빡임 0건)

```json
{"상태": "발생", "공간": "사무실", "종류": "환기", "설명": "환기 필요: 30분 내 최대 1020ppm", "시각": "2026-10-15T09:48:00+09:00"}
{"상태": "해제", "공간": "사무실", "종류": "환기", "시작": "2026-10-15T09:48:00+09:00", "지속분": 37, "시각": "2026-10-15T10:25:00+09:00"}
```

## 상태 (`/status`, `/health`)
```json
{"alive": true, "last_cycle": "2026-10-15T10:03:00+09:00", "ok": true, "ms": 410.2, "version": "service v1 ...", "active_alarms": 1}
```

## 가동 기록
- `~/ts-data/service_log.jsonl`: 주기마다 `{"type":"cycle","time","ok","ms"}`, 경보가 있으면 `{"type":"alarm","events":[...]}`
- `python service.py --summary`: 가동 시간, 2분 넘게 빈 구간, 처리 시간(평균·p95·최대), 실패, 경보 내역
