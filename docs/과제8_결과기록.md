# 과제 8 — 상시 추론 서비스 결과 기록 (10/22)

## 구성
- 젯슨 Orin Nano Super(team4)에서 systemd 서비스 2개를 상시 실행. 재부팅되면 자동으로 시작하고, 죽으면 5초 뒤 다시 시작함.
  - `ts-collector`: MQTT 센서 업링크 → 로컬 SQLite(`live.db`)
  - `ts-infer`: 매분 실행. 최근 2일치를 학습과 같은 전처리(features.py, import로 공유)로 정리하고, GRU·오토인코더·MLP를 ONNX Runtime CPU로 실행해 결과를 발행함
- 출력: MQTT retained `ts-team4/inference/room/{office,lab,meeting}`, `/status`(LWT로 죽음 알림), `/alarm`(이벤트). HTTP `:8425` `/latest`, `/alarms`, `/health`. 결과 형식은 과제8_결과형식.md 참고.
- 실제 데이터에 맞춰 바꾼 것:
  - 게이트웨이 1대 시계가 약 5분 빠름 → 메시지 `time` 대신 네트워크 서버 수신 시각(`nsTime`)을 씀
  - 8000번 포트를 다른 서비스가 쓰고 있음 → API를 8425번으로 옮김
  - 경보가 켜졌다 꺼졌다 반복함 → 15분 동안 다시 안 걸려야 해제

## 한계와 개선점
- **재시작하면 경보 상태가 사라짐.** 손 시험 프로세스와 상시 서비스가 각각 회의실 "데이터 끊김"을 "발생"으로 보낸 것이 그 예. 경보 상태를 파일에 저장하면 재시작 뒤에도 이어짐.
- 처리 시간 대부분은 2일치 전처리(5분 칸 합치기)임. 모델 실행 자체는 ms 단위(과제 7). 필요하면 지난 주기의 정리 결과를 재사용해 줄일 수 있음.
- 이상 탐지 성능은 실제 고장이 없어서 가동 중에 확인하지 못함. 헛경보가 0회라는 것만 확인함.
