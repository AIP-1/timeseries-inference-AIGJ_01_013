# 과제 8 — 젯슨 설치·실행 순서

붙여넣은 파일은 매번 `sed -i '1s/^[[:space:]]*//' 파일이름` 으로 첫 줄 공백 제거.

## 1. 파일 넣기 (~/ts-data/)
- 새 파일: `features.py`, `collector.py`, `service.py`
- 바뀐 파일: `clean.py` (features.py를 import하도록 바뀜, 결과는 같음)
- 이미 있어야 하는 것: `gru_co2_norm.json`, `state_mlp.json`, `co2_room_5min.pkl`, `temperature_room_5min.pkl`, `edge/gru.onnx`, `edge/ae.onnx`, `edge/mlp.onnx`

## 2. 라이브러리
```bash
source ~/ts-venv/bin/activate
pip install paho-mqtt
python -c "import numpy, paho.mqtt; print(numpy.__version__)"     # 1.26.4 여야 함. 2.x면 pip uninstall -y numpy
```

## 3. 접속 정보 (.env)
`service/env.example` 내용을 `~/ts-data/.env` 로 붙여넣고 브로커 주소·아이디·비밀번호·토픽을 채움.
```bash
chmod 600 ~/ts-data/.env
```
구독 토픽을 모르면 브로커에서 실제 토픽을 먼저 확인 (mosquitto-clients 필요, 5개 보고 끝남):
```bash
mosquitto_sub -h <브로커> -u <아이디> -P '<비밀번호>' -t '#' -v -C 5
```

## 4. 손으로 먼저 시험
```bash
cd ~/ts-data
timeout 120 python -u collector.py                     # 2분 수집 후 자동 종료
python -c "import sqlite3; d=sqlite3.connect('live.db'); print(d.execute('select location, meas, count(*), max(time) from readings group by 1,2').fetchall())"
python service.py --once --no-mqtt > once.txt 2>&1; head -60 once.txt
```
처음 실행 때 `service_params.json`(정규화 값·오토인코더 기준)이 만들어짐. 수집이 2시간 안 됐으면 예측은 "판단 불가"가 정상.

## 5. 상시 실행 (systemd)
`service/ts-collector.service`, `service/ts-infer.service` 두 파일을 `/etc/systemd/system/` 에 붙여넣고:
```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ts-collector ts-infer
systemctl status ts-collector ts-infer --no-pager | head -20
curl -s localhost:8425/health; echo
curl -s localhost:8425/latest/office | head -c 600; echo
```
재부팅해도 자동 시작, 죽으면 5초 뒤 다시 시작.

## 6. 12시간 가동 + 수집기 10분 정지 시험
```bash
sudo systemctl stop ts-collector; sleep 600; sudo systemctl start ts-collector    # 가동 중 아무 때나 한 번
python service.py --summary > summary.txt; cat summary.txt                          # 12시간 뒤
```
요약에 "수집 끊김"·"데이터 끊김" 발생과 해제가 찍히고, 주기 사이 2분 넘게 빈 곳이 없어야 함.
