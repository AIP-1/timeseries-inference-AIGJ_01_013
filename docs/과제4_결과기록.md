# 과제 4 — 이상 탐지 결과 기록 (10/20)

## 평가 방식 (가정)
- 키트의 "고장 정답 주"가 없어 **시험 기간(10/5~10/18)에 고장 5종을 직접 심음**: 공간 3곳 × 종류 5 × 2번 = 30건. 정답 파일 `anomaly_labels.csv`.
  - 튄 값: CO₂ 한 칸 +800ppm / 값 고정: CO₂ 3시간 같은 값 / 영점 틀어짐: CO₂ 6시간 +200ppm
  - 냉방 정지: 평일 낮 온도 4시간 동안 +2.5℃까지 서서히 / 환기 정지: 평일 낮 CO₂ 3시간 동안 +400ppm까지 추가 상승
- 학습은 학습 기간(정상)만. 임계값은 v4까지 "검증 기간(고장 없음) 헛경보 하루 1회 이하 중 가장 낮은 값", **v5부터 검증 기간에도 고장 30건을 따로 심고, 오토인코더·예측 잔차 임계값 36개 조합 중 검증 헛경보 1회/일 이하에서 검증 탐지율이 가장 높은 조합**을 선택. 시험 기간은 평가에만 사용.
- 30분 안에 이어지는 경보는 한 건. 탐지는 **고장 진행 중** 울린 경보만 인정. 고장 끝난 뒤 1시간 안의 경보는 탐지도 헛경보도 아님.
- 헛경보 = 고장과 겹치지 않는 경보 건수 ÷ 14일, 공간 합.

## 탐지기
- 모델: 오토인코더(1시간 창, CO₂·온도 수준과 변화) + 예측 잔차(1시간 전 선형 예측보다 실제 CO₂가 많이 높으면)
- 규칙: 급변(CO₂ 500ppm·온도 2℃/5분), 값 고정(1시간), 범위 밖, 온도 상승(평일 09~18시 2시간 +1℃), 계단(잔잔한 30분 사이 평균 120ppm 차이)

## 버전별 결합 성적 (시험)
| 버전 | 바꾼 것 | 탐지율 | 헛경보/일 |
|---|---|---|---|
| v1 | 오토인코더 + 기본 규칙 | 93% | 0.57 | ← 고장 끝난 뒤 1시간까지 탐지로 인정해 **부풀려짐**(냉방·환기 정지 지연 = 고장 길이 → 복구 순간 급변을 잡은 것) |
| v2 | 진행 중 경보만 인정, 온도 상승 규칙 | 70% | 0.86 |
| v3 | 계단 규칙, 예측 잔차 | 77% | 1.00 |
| v4 | 검증 헛경보 분석 후 규칙 조정 | 77% | 0.79 |
| v5 | 검증 기간에도 고장을 심어 두 모델 임계값을 따로 선택 | **80%** | **0.86** |

v3 검증 기간 탐지기별 헛경보/일: 온도 상승 0.64(퇴근 후 냉방 꺼짐), 회의실 급변 0.21·값 고정 0.14(10분 간격 센서) → v4에서 조정.

## 최종(v5) 종류별 (시험, 결합) — 확인 기준(탐지 80% 이상, 헛경보 1회/일 이하) 충족
| 종류 | 탐지 | 평균 지연 |
|---|---|---|
| 튄 값 | 6/6 | 0분 |
| 값 고정 | 6/6 | 46분 |
| 냉방 정지 | 6/6 | 52분 |
| 영점 틀어짐 | 4/6 | 15분 |
| 환기 정지 | 2/6 | 65분 |

성적표(v5): 모델 30%/0.43회, 규칙 77%/0.64회, **결합 80%/0.86회**. 원인 센서 적중 92%.
임계값별(시험, 두 모델 같은 분위수): 0.99 → 87%/1.43회, 0.995 → 87%/1.14회, 0.998 → 80%/0.93회, 0.999 → 80%/0.86회, 0.9999 → 77%/0.71회.

## 못 잡는 종류와 이유
- **영점 틀어짐**: +200ppm은 실내 정상 범위 안이라 수준만 봐서는 구별 불가. 사람이 드나드는 시간에 생기면 계단 규칙(잔잔할 때만)도 놓침. 공간 평균만 써서 센서 간 비교 신호가 사라짐 → 실습실처럼 센서가 여럿인 곳은 **센서끼리 비교**가 개선안.
- **환기 정지**: 수업 시작 때 자연 상승(1시간 수백 ppm)과 비슷함. 예측 잔차가 잡지만 헛경보 한도 때문에 임계값이 높아짐. 9/21 이후 사용 패턴 변화로 검증 기간 잔차가 커진 것도 원인(추정).
- 오토인코더 단독은 1시간 창이라 느린 고장을 정상으로 봄 → 빠른 고장(튄 값) 위주.

## 운영 제안
- 규칙(빠르고 설명 쉬움) + 예측 잔차(느린 고장)를 함께 쓰고, 경보에 원인 센서 표시.
- 헛경보 한도를 하루 1.2회로 늘리면 탐지율 87%(시험 0.995 기준) — 운영자와 합의할 트레이드오프.
- 임계값은 고장을 심은 검증 기간으로 고르는 방식이 효과적이었음(v4 77% → v5 80%).
- 냉방·환기 정지는 HVAC 상태(MQTT xflow/hvacr) 신호와 결합하면 직접 확인 가능.

## README 고장 모양으로 다시 실행 (10/21, v6·v7)
v5의 고장은 README보다 쉬운 모양이었음 → README대로 바꿔 다시 평가.
| 고장 | v5 (이전) | v6~ (README) |
|---|---|---|
| 영점 틀어짐 | 한 번에 +200ppm | 6시간에 걸쳐 300~500ppm 서서히 |
| 냉방 정지 | 4시간 +2.5℃ | 수업 중 4시간 +3~5℃ |
| 환기 정지 | 3시간 +400ppm 더함 | 사용 중(CO₂ 오르는 3시간) 상승 폭 1.8배 |

- v6: 탐지 방법은 v5 그대로 → **결합 60% / 1.14회/일**. 영점 틀어짐 0/6, 환기 정지 1/6.
- v7: 느린 고장용 탐지기 3개 추가(임계값은 검증 분위수, 조합 6×6×5에서 선택)
  - 바닥값: 밤·쉬는 날 CO₂의 최근 1시간 최솟값 − 하루 전까지 7일간 빈 시간 하위 10%
  - 3시간 예측 잔차: 3시간 전 릿지 예측보다 실제가 높은 정도
  - 상승 속도: 1시간 상승 폭
  - 결과 **결합 70% / 1.21회/일** (모델 33%/0.50, 규칙 57%/0.79)

| 종류 (v7 결합) | 탐지 | 평균 지연 |
|---|---|---|
| 튄 값 | 6/6 | 0분 |
| 값 고정 | 6/6 | 55분 |
| 냉방 정지 | 5/6 | 41분 |
| 영점 틀어짐 | 3/6 | 300분 |
| 환기 정지 | 1/6 | 55분 |
임계값별(시험): 0.99 → 80%/2.00회, 0.995 → 77%/1.86회, 0.999 → 73%/1.50회, 0.9999 → 70%/1.14회.

- **README 모양에서는 확인 기준(80%, 1회/일 이하) 미충족.** 80%는 헛경보 하루 2회에서만 나옴. v5의 80%는 고장이 쉬운 모양이라 나온 값 → 보고서에는 v7을 주 결과로, v5는 "단순한 고장 모양일 때"로 함께 적는 게 정직함.
- 영점 틀어짐: 바닥값·3시간 잔차로 0→3건. 지연 300분 = 6시간 중 거의 끝에서야 잡음(수백 ppm까지 쌓여야, 또는 밤·빈 시간이 와야 드러남). 사람이 있는 낮에 시작한 틀어짐은 사용에 의한 상승과 구별이 안 됨.
- 환기 정지(1.8배)는 여전히 1/6: 사람 수가 매번 달라 "평소 상승 폭"의 폭이 넓어서, 1.8배여도 정상 범위 안에 들어감. 인원·HVAC 상태 없이 CO₂만으로는 근본적으로 어려움.
- 검증에서 고른 임계값이 시험에서 헛경보 1.21회로 한도를 넘음 → 9/21 이후 사용 패턴이 계속 바뀌는 영향(추정).
- 개선 방향: 실습실 센서 4개끼리 비교(한 센서만 틀어지면 바로 보임), HVAC 상태(MQTT xflow/hvacr)와 결합.

| 버전 | 바꾼 것 | 시험 결합 탐지율 | 시험 헛경보/일 | 검증 헛경보/일 |

- v8 진단(검증 3벌, 분위수 0.999): **공간 간 차이가 영점 틀어짐 18건 중 10건을 헛경보 0.19회/일로 잡음** — 영점 틀어짐에 가장 효율적인 탐지기. 3시간 잔차는 영점 6·환기 8건(0.40회).
- v9~v10: 탐지 80%는 넘지만 시험 헛경보가 검증보다 1.6배 많음. 원인: 임계값을 검증 분위수로 만들고 같은 검증 기간에서 헛경보를 세서 낙관적으로 추정됨.
- v11: 그 낙관을 없애니 선택이 보수적으로 바뀌어 헛경보는 한도 안, 탐지는 70%(규칙만 쓴 것과 같음).
- v11 헛경보 한도별: 검증 한도 1.5 → 시험 80% / 1.21회. 지금까지 시험 결과를 모으면 이 데이터·고장 모양에서는 **탐지 80% 근처에서 헛경보 하루 1.1~1.2회**가 한계선.
- 결론: README 모양 고장으로는 두 기준을 동시에 넘기지 못함(가장 가까운 것: v10 83%/1.14회). 시험 기간을 보고 고르면 넘길 수 있지만 누수라 하지 않음.

## 최종 선택 (10/21): v10 — 결합 83% / 헛경보 1.14회/일
- 탐지 기준(80%) 충족, 헛경보 기준(1회/일)은 0.14회 초과. 임계값·탐지기 선택은 검증 기간만 사용(시험 미사용).
- 보고서에 함께 적을 것: 검증 헛경보(0.69)가 시험(1.14)보다 낮게 추정된 이유(임계값 만든 기간에서 헛경보를 셈)와, 이를 고친 v11(70%/0.71)의 결과 → "탐지 80% 근처에서 헛경보 1.1~1.2회/일"이 이 데이터의 한계선.
- 최종 코드: anomaly.py (= anomaly_v10.py). 이전 버전은 anomaly_v5~v11.py로 보관.
